01 / Semantic Layer & Metrics Governance

One definition. Consistent reporting.

The problem
Finance and operations can report different numbers under the same metric name. Without shared definitions, leadership cannot compare results reliably.
What I built
Built a versioned KPI registry with ownership, approvals, and change history. PostgreSQL and dbt produce governed metrics; a reconciliation layer compares 25 DAX measures and flags definition drift.

03 / Transaction Reconciliation Assistant

Reconcile with SQL. Explain with evidence.

275controlled exceptions identified
PythonPostgreSQLpgvectorFLAN-T5RAG
The problem
Operations teams need to identify ledger mismatches and find the policy passages relevant to follow-up.
What I built
Used SQL to classify transaction breaks, then combined pgvector and full-text retrieval with a local FLAN-T5 model to produce explanations with page-level citations.
Measured result
Reconciled 25,000 synthetic source transactions and indexed 1,128 passages from a 439-page manual. Retrieval achieved 100% Hit@5 on an initial set of 10 labeled questions.
  1. Ledger comparison
  2. SQL exceptions
  3. Hybrid retrieval
  4. Cited explanation

Independent RAG prototype · synthetic ledgers and the archived 2010 FFIEC manual · small initial evaluation.

Implementation & evaluation notes

SQL determines the reconciliation result; retrieved text cannot change it. Hit@5 measures whether a relevant passage appears among the top five results. The 10-question evaluation is an initial benchmark, not a broad accuracy claim. The archived manual provides a stable reference dataset, not current compliance guidance.
